# Мини-CRM

Личная картотека клиентов, сделок, заказов и задач. Данные лежат в файле SQLite на этом компьютере. Окно программы ходит к локальному серверу по HTTP и само базу не открывает.

Это не сайт. Адрес `http://127.0.0.1:8000/` — корень API, а не интерфейс. Карточки правятся в окне на рабочем столе. Описание API открывается в браузере по адресу `http://127.0.0.1:8000/docs`.

## Структура

```text
.
├── README.md                 описание для пользователя
├── requirements.txt          зависимости окна, выгрузки и скрипта заполнения
├── seed_crm.py               тысяча клиентов, сделок и задач через API
├── backend/                  сервер и база
│   ├── api.py                HTTP-методы FastAPI, префикс /api/v1
│   ├── crm.py                чтение и запись карточек
│   ├── models.py             таблицы, статусы и проверки
│   ├── Dockerfile
│   ├── docker-compose.yml    сервер на 127.0.0.1:8000 с перезапуском по правке .py
│   ├── requirements.txt      зависимости только сервера
│   └── data/crm.sqlite       база; создаётся сама и в репозиторий не входит
├── ui/                       окно мини-CRM
│   ├── crm_app.py            таблицы, поиск, карточки
│   ├── google_export.py      выгрузка видимой таблицы в Google
│   ├── google_settings.txt   пути к JSON и папка Диска; создаётся в окне
│   └── google_oauth_token.json   вход Google; появляется после первого входа
└── reports/                  отдельное окно генератора отчётов и клиенты Google
    ├── app.py                форма периода и модельных цифр
    ├── report_model.py       расчёт такого отчёта
    ├── google_drive.py       создание файла на Диске от личного аккаунта
    ├── google_sheets.py      запись и оформление листа
    └── .env.example          образец настроек для reports/app.py
```

Папка `.venv` ставится локально. JSON-ключи Google, `.env`, токен входа и файл базы в репозиторий не попадают: они перечислены в `.gitignore`.

## Что хранится

Четыре карточки. Суммы сделок и заказов в базе лежат в копейках, в окне показываются рублями.

| Раздел | Что в карточке |
| --- | --- |
| Клиенты | Имя, компания, телефон, почта, источник и статус: потенциальный, действующий, неактивный, архив. |
| Сделки | Название, сумма, валюта, ожидаемая дата и воронка. Клиента можно не указывать и привязать позже. |
| Заказы | Название, сумма, срок и статус. Заказ может ссылаться на клиента и на сделку. |
| Задачи | Название, подробности, срок, отметка «выполнена». Это задача или напоминание. Связь — с клиентом, сделкой или заказом, можно и без связи. |

Поиск не различает регистр и буквы «е» и «ё». В окне за раз видно 100 строк. Кнопки **Назад** и **Дальше** листают остальные. Внизу написано, какой это диапазон, например «Показаны 1–100 из 1003».

## Первый запуск

Нужны Python 3.12 и, если сервер поднимается в Docker, установленный Docker. Команды ниже выполняются из корня проекта.

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

Сервер — один из двух способов. Оба занимают порт `127.0.0.1:8000`, одновременно их запускать не нужно.

Docker, с перезапуском при изменении файлов `.py` в папке `backend`:

```powershell
cd backend
docker compose up -d --build
```

Без Docker, в отдельном окне консоли:

```powershell
.\.venv\Scripts\python.exe backend\api.py
```

Окно CRM:

```powershell
.\.venv\Scripts\python.exe ui\crm_app.py
```

Кнопка **Подключиться** заново читает сводку и таблицы. Кнопка **Запустить сервер** открывает `backend\api.py` в новой консоли. Если порт уже занят Docker, эта кнопка сервер не поднимет.

Файл базы появится сам: `backend\data\crm.sqlite`. Каталог можно сменить переменной `CRM_DB_PATH`.

## Окно

Четыре вкладки: клиенты, сделки, заказы, задачи. На каждой есть поиск, фильтр, таблица и кнопки **Создать**, **Изменить**, смена статуса или отметки «выполнена», **Удалить**. Двойной щелчок открывает карточку. Клавиша Delete удаляет выбранную строку.

Удаление клиента не удаляет его сделки, заказы и задачи: связь с ним просто снимается.

## Выгрузка в Google

Кнопка **Выгрузить отчёт** на вкладке создаёт новую Google Таблицу в выбранной папке и записывает в неё строки, которые сейчас видны на экране, вместе с короткой сводкой.

Перед первой выгрузкой нажмите **Настройки Google** и укажите три вещи:

1. JSON OAuth-клиента (`client_secret_….json`) — им программа входит в ваш Google-аккаунт. Браузер откроется один раз, дальше используется сохранённый токен.
2. JSON сервисного аккаунта (`excel-factory-….json`) — им программа записывает ячейки. Файл создаёт личный аккаунт и открывает его этому адресу как редактору.
3. Папка на Google Диске. Вставьте ссылку вида `https://drive.google.com/drive/folders/…` кнопкой **Вставить** или впишите сам идентификатор папки. Ссылка на уже существующую таблицу сюда не подходит.

Оба JSON лежат в `reports/` и в git не коммитятся. После записи окно показывает ссылку и кнопку **Открыть**.

Старые пустые таблицы, созданные до исправления записи, сами не заполняются. Их можно удалить и выгрузить отчёт ещё раз.

## Пробные данные

Когда сервер уже отвечает, скрипт добавит около тысячи клиентов, тысячи сделок и тысячи задач. Это занимает несколько минут. Заказы скрипт не создаёт, вкладка заказов после него останется пустой, если заказы не заводили вручную.

```powershell
.\.venv\Scripts\python.exe seed_crm.py
```

## Генератор отчётов

В `reports\` осталось отдельное окно. Оно не читает CRM. Человек задаёт период, подразделение, вид отчёта и ответственного, программа придумывает цифры по дням и записывает их новым листом в уже существующую Google Таблицу. Сводка и строка «Итого» на листе считаются формулами.

Настройки этого окна — файл `reports\.env` по образцу `reports\.env.example`: идентификатор таблицы, при необходимости путь к JSON-ключу. Таблицу нужно открыть сервисному аккаунту с ролью редактора.

```powershell
copy reports\.env.example reports\.env
.\.venv\Scripts\python.exe reports\app.py
```

Период не длиннее 62 дней, даты вводятся как `ДД.ММ.ГГГГ`.
